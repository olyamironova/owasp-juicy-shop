# Playwright Test для поиска в Juice Shop

13 UI-сценариев из `ПР7_2-2.docx`, JavaScript и Chromium. Нумерация следует
новому отчёту: `berr` — TC04, дефис — TC10, точка — TC11.
Учебный тест счётчика сохранён отдельно в `tests/counter.spec.js`.

Для учебного разбора отчёта изменены ожидания в TC01, TC02 и TC04.
В TC01 ожидается Banana Juice вместо Apple Juice, в TC02 — ноль результатов
для Apple, в TC04 — отсутствие Berry Juice в выдаче berr. Поэтому ожидаются
3 падения из-за ошибок ожидания. Исходные названия и группы тестов сохранены.
Эти падения не являются найденными дефектами магазина.

## Быстрый запуск

Запустите Docker Desktop и локальный Juice Shop:

```sh
git clone https://github.com/olyamironova/owasp-juicy-shop.git
cd owasp-juicy-shop
docker compose up -d
```

Затем из той же папки установите зависимости и запустите сценарии поиска:

```sh
npm ci
npm run browsers:install
npm run test:search
```

Адрес по умолчанию: `http://127.0.0.1:3001`. Для другого адреса:

```sh
BASE_URL=http://127.0.0.1:3002 npm run test:search
```

В `compose.yaml` закреплён официальный образ `bkimminich/juice-shop:v20.4.0`; магазин доступен только на `127.0.0.1:3001`.
Остановить стенд: `docker compose stop`.

Тесты не поднимают сервер магазина автоматически. Каждый сценарий получает
отдельный контекст браузера без авторизации, с языком English и окном 1280×900.
Запуск последовательный (`workers: 1`), чтобы браузеры не конкурировали за ресурсы локального стенда.
Сценарии не создают пользователей и не меняют каталог или заказы.

## Команды

| Действие | Команда |
| --- | --- |
| Все тесты | `npm test` |
| Только сценарии отчёта | `npm run test:search` |
| Один сценарий | `npm run test:search -- -g TC04` |
| Поиск с видимым браузером | `npm run test:search -- --headed` |
| Поиск в интерактивном режиме | `npm run test:search:ui` |
| Один сценарий с отладчиком | `npm run test:search -- -g TC04 --debug` |
| Предложенные требования | `npm run test:search -- --grep @proposed` |
| Исследовательские сценарии | `npm run test:search -- --grep @exploratory` |
| Только счётчик | `npm test -- tests/counter.spec.js` |
| С видимым браузером | `npm run test:headed` |
| Интерактивный режим | `npm run test:ui` |
| Пошаговый отладчик | `npm run test:debug` |
| HTML-отчёт | `npm run report` |
| Генератор тестов | `npm run codegen -- http://127.0.0.1:3001` |

`npm run report` запускает локальный сервер отчёта. Адрес появится в терминале;
для остановки нажмите Ctrl+C. Чтобы избежать конфликта с уже запущенным
сервером отчёта, можно указать `npm run report -- --port 9324`.

## Покрытие отчёта

| Группа | Сценарии |
| --- | --- |
| G1 Базовый поиск | TC01 полное название, TC02 Apple, TC03 Juice, TC04 berr |
| G2 Нормализация запроса | TC05 apple/APPLE, TC06 внешние пробелы |
| G3 Обновление и пагинация | TC07 Apple → Banana, TC08 страницы выдачи Juice |
| G4 Очистка запроса | TC09 возврат к исходному каталогу |
| G5 Знаки препинания | TC10 дефис, TC11 точка после дефиса |
| G6 Навигация | TC12 перезагрузка, TC13 открытие и закрытие карточки |

TC05, TC06 и TC12 помечены `@proposed`: в отчёте их ожидаемое поведение
названо предложенным требованием. Проверки выполняются строго, без `skip`,
`fixme`, ожидаемых падений или автоматических повторных запусков.

TC10 и TC11 помечены `@exploratory`, поскольку в отчёте ожидания стоят как `???`.
Они проверяют, что интерфейс принимает запрос и позволяет собрать выдачу, и
прикладывают списки товаров и скриншоты к HTML-отчёту. Для TC11 сохраняются
также пересечения и различия двух выдач. Зелёный статус этих двух сценариев
означает успешный сбор наблюдений, а не подтверждение корректности поиска.
Равенство или различие результатов заранее не навязывается.

В TC01–TC04 проверяются конкретные совпадения, названные в отчёте. Точное
полное множество допустимых совпадений не задано: поля поиска в отчёте не
согласованы. Поэтому тесты не объявляют ошибкой каждый дополнительный товар.

Пагинация проходится через UI целиком; при сравнении множеств порядок не
учитывается. TC08 явно проверяет предусловие `> 15` и размер страницы 15.
Если предусловие нарушено, тест падает с пояснением, а не пропускается.

## Что подготовлено

- `compose.yaml`: локальный запуск Juice Shop.
- `playwright.config.js`: Chromium, консольный, HTML- и JSON-отчёты.
- `tests/search.spec.js`: 13 сценариев нового отчёта.
- `tests/helpers/juice-shop.js`: действия поиска, обход страниц и вложения.
- `tests/counter.spec.js`: проверка начального значения 0 и значения 1 после нажатия.
- При падении сохраняются скриншот и трасса в `test-results/`.
- HTML-отчёт записывается в `playwright-report/`.
- Фактические выдачи сохраняются как JSON-вложения в отчёт каждого теста.
- `package-lock.json` фиксирует установленные версии зависимостей.

## Повторная установка

Потребуются поддерживаемая версия Node.js (22, 24 или 26), npm и доступ к сети:

```sh
npm ci
npm run browsers:install
npm test
```

## Особенности стенда

Тесты подготовлены для OWASP Juice Shop v20.4.0. Локаторы зависят от
английских доступных имён элементов и текущей структуры карточек.
Название товара используется как уникальный идентификатор исходного каталога.
Время ожидания основано на состоянии URL, заголовка, карточек и пагинации;
фиксированных `waitForTimeout` нет.

В этой версии UI загружает полный каталог и фильтрует его в браузере.
API `/rest/products/search?q=...` использует другой механизм поиска;
его ответы не подставляются вместо ожидаемых результатов UI.

Источники:

- https://github.com/juice-shop/juice-shop/blob/v20.4.0/frontend/src/app/search-result/search-result.component.ts
- https://github.com/juice-shop/juice-shop/blob/v20.4.0/routes/search.ts

## Сохранённый отчёт

Полный HTML-отчёт последнего проверенного прогона находится в `reports/latest/`.
Он содержит 14 тестов: 11 passed и 3 failed. Исходные названия сценариев сохранены.
Внутри находятся вложения, скриншоты и трассы для упавших тестов.
`run-summary.json` содержит итог прогона и SHA-256 проверенных исходников.

После установки зависимостей открыть сохранённый отчёт можно командой:

```sh
npm run report -- reports/latest
```

Для просмотра последнего нового локального прогона используйте `npm run report`.
GitHub показывает исходный HTML, поэтому интерактивный отчёт нужно открывать
локально указанной командой после клонирования репозитория.
